## 1. نظرة عامة على النظام والبيئة

نظام ماركوس هو محرك تشغيلي متكامل لإدارة طلبات التجارة الإلكترونية بنظام الدفع عند الاستلام (Cash on Delivery) في مصر، ويتكون من:
1. **الخادم الخلفي (API Layer):** مبني على Node.js وExpress مع Zod للتحقق من المدخلات، وتوحيد رقم الهاتف المصري بصيغة E.164.
2. **محرك منع التكرار (Anti-Duplicate Engine):**
   - مستوى 1: فحص ترويسة `Idempotency-Key` وبصمة الطلب المشفرة لمنع الحفظ المضاعف عند تكرار النقر.
   - مستوى 2: خوارزمية كشف الطلبات المتطابقة بالهاتف والمنتج خلال نافذة 72 ساعة لإحالتها للمراجعة البشرية.
3. **آلة حالات الطلب (Strict State Machine):** ضبط صارم لانتقالات الحالات مع فرض الأسباب الإلزامية وبيانات بوليصة الشحن.
4. **لوحة الإدارة:** واجهة RTL عربية سريعة مع مؤشرات توقيت القاهرة وتحليلات الحملات والربط مع شركات الشحن المصرية (بوسطة، مايلرز، أرامكس).

## 2. إجراءات بدء التشغيل وإدارة البيئات

### 2.1 المتغيرات البيئية (.env)
```bash
# منفذ الخادم (الافتراضي 3000)
PORT=3000

# بيئة التشغيل (development / production)
NODE_ENV=production

# رابط النشر العام
APP_URL="https://your-domain.com"
```

### 2.2 أوامر التشغيل والاختبار
```bash
# تشغيل خادم التطوير مع مراقبة التغييرات
npm run dev

# تشغيل حزمة الاختبارات الآلية والتحقق من القواعد الصارمة
npm test

# فحص كود TypeScript
npm run lint

# بناء نسخة الإنتاج
npm run build

# تشغيل نسخة الإنتاج
npm start
```

## 3. التعامل مع الحوادث والأخطاء التشغيلية

### 3.1 خطأ التعارض التزامني (409 STATE_CONFLICT)
- **السبب:** قام شخصان أو عمليتان بتعديل حالة الطلب في نفس اللحظة (عدم تطابق `version`).
- **الإجراء:** يقوم النظام تلقائيًا بإعادة جلب أحدث بيانات للطلب وعرضها للمالك لتجنب الكتابة فوق تعديل أحدث.

### 3.2 خطأ إعادة استخدام المفتاح (409 IDEMPOTENCY_KEY_REUSED)
- **السبب:** إرسال طلب جديد بنفس مفتاح `Idempotency-Key` لطلب سابق ولكن ببيانات مختلفة.
- **الإجراء:** توليد مفتاح جديد فريد من صفحة الهبوط (`crypto.randomUUID()`).

### 3.3 حسم تنبيهات التكرار المعلقة (Duplicate Review)
- عند تطابق رقم الهاتف ونفس المنتج خلال 72 ساعة، يدخل الطلب في حالة `PENDING_REVIEW`.
- يقوم موظف خدمة العملاء بالتواصل مع العميل لحسم:
  - **ليس مكررًا (KEPT):** العميل يرغب في شراء كميتين بطلبين منفصلين.
  - **مكرر (CANCELLED_AS_DUPLICATE):** إلغاء الطلب الأحدث آليًا مع توثيق السبب وإلغاء مهمة المتابعة.

## 4. سياسة التصدير والنسخ الاحتياطي والأمان

1. **النسخ الاحتياطي:** يتم جدولة تصدير لقاعدة البيانات وسجل التدقيق بصفة دورية.
2. **تصدير CSV الآمن:** كافة ملفات CSV المصدّرة مشفرة بـ `UTF-8 BOM` لضمان قراءة الحروف العربية في Microsoft Excel، مع تعقيم الرموز (`=`, `+`, `-`, `@`) لمنع هجمات حقن المعادلات (Formula Injection).
3. **سجل التدقيق (Audit Logs):** سجل إلحاقي فقط (Append-only) يرفض التعديل والحذف لحماية السجلات المالية والتشغيلية.
